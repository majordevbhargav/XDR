Cisco XDR Automation: Work Summary

What was built in the Cisco XDR proof-of-value (POV) environment for the "Response / Automation / Workflow" (R.A.W) requirements, why it was built, and how the parts fit together.

1. Purpose

The POV requirements sheet asks Cisco XDR to show that it can respond to threats faster, using automation instead of manual steps. The R.A.W section has four tests: create a ticket, complete a containment workflow, create a trigger, and create a custom playbook. This work covers the trigger and the playbook, and prepares the ground for the other two.

2. Key terms in plain language

TermMeaning
IncidentA group of related security alerts that XDR combines into one case, with a priority score.
WorkflowA low-code flowchart that performs steps automatically (send a message, call another system, make a decision).
Automation ruleA "when this happens, run that" instruction. It starts a workflow when an incident matches conditions.
PlaybookA phased checklist that guides an analyst through responding to an incident. Tasks can be manual or run a workflow.
Assignment ruleDecides which playbook is attached to a new incident.
Target and account keyThe saved connection to an outside system, and the stored login it uses.
WorklogThe record of everything that happened on an incident.

3. How the parts fit together

New incident→Automation rule checks conditions→Workflow runs automatically
New incident→Assignment rule attaches playbook→Analyst works the tasks→Worklog records it

The automation rule and workflows are the automatic side: they act without anyone clicking. The playbook is the guided side: it tells an analyst what to do next and records that it was done. A playbook task can also run a workflow, so the two meet at that point.

6. Suggested description text

These can be pasted into the description fields so others understand each object.

Rule-Test workflow

Test workflow with an Incident Response intent. Runs when an automation rule fires on an incident, and sets a note variable. Used to verify that rules start workflows and as a placeholder task in the HCL playbook.

Automation rule

Runs for incidents whose priority score is above 800, to notify the response team and start automated steps. Evaluated when an incident is created or its status changes.

Playbook

Standard triage, containment and closure steps for the HCL POV. Guides an analyst through identification, containment, eradication and recovery.

Playbook tasks

Review incident summary and affected assets: Read the incident summary, note the main affected assets in the worklog.
Check observable verdicts: Look up each observable's verdict and record any that are malicious.
Run test workflow: Run the linked workflow and confirm it completes successfully.
Contain affected host: Isolate the affected endpoint after approval, and record the result.
Document findings and close incident: Summarize what happened, actions taken and lessons, then close the incident.

7. What has been demonstrated

  • Workflows can be built in the low-code editor, validated, run, and inspected step by step.
  • An automation rule starts a workflow by itself when an incident matches its conditions. The workflow run history shows the rule as the starter.
  • A custom playbook with task phases can be created and published, and tasks can be manual or run workflows.

8. Open items

Not yet done. These are honest gaps, not failures.
  • Email delivery: the email workflow needs an SMTP account that accepts a password sign-in from XDR (for example a Gmail app password, or the company mailbox once IT enables authenticated SMTP). Until then, the "trigger sends an email" part is not proven.
  • Assignment rule: create or confirm it, then walk a new incident through the playbook. Existing incidents cannot receive the playbook.
  • Task descriptions: replace the placeholder text under some tasks with real instructions.
  • Create Ticket (ServiceNow): not started. Needs a ServiceNow instance and credentials.
  • Complete Containment: not started. Needs the endpoint tool integration (CrowdStrike) and a lab host. It will replace the placeholder containment task.
